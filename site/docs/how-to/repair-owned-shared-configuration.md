# How to repair owned shared configuration

This guide shows how to reconcile Devin or Codex shared configuration files when `agent-marketplace` cannot prove ownership of an existing entry.

## Prerequisites

- `agent-marketplace` on your `PATH`.
- A terminal where `agent-marketplace doctor` reports a Devin or Codex ownership issue.

## 1. Run a diagnostic

```bash
agent-marketplace doctor
```

Look for diagnostics such as `ownership.state-missing`, `ownership.unmanaged-key`, or `materialize.codex.trust-review`.

## 2. Open the repair prompt

```bash
agent-marketplace doctor --repair
```

The command classifies each unmanaged or conflicting entry:

- **Exact match**: the existing entry matches the desired entry and can be adopted.
- **Orphan**: the entry was generated by a previous run and is no longer selected; it can be removed.
- **Replaceable conflict**: the key matches but the value differs; it can be replaced after you confirm.

## 3. Batch safe adoptions

To adopt every exact match without per-entry prompts:

```bash
agent-marketplace doctor --repair --yes
```

`--yes` does not authorize orphan removal or conflict replacement. Those still require interactive confirmation.

## 4. Verify

```bash
agent-marketplace sync --check
```

The shared configuration should now be in sync.

## Boundaries

- `doctor --repair` never removes or overwrites an entry without interactive confirmation.
- A fresh safety backup is taken before any replacement.
- Missing ownership state is a fail-closed condition: every existing entry is treated as unmanaged.
