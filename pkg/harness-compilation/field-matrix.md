# Rich IR field matrix (D2)

This matrix records all seven targets. The main table includes Devin; Codex mappings follow in a separate table so the dense cells remain reviewable. `emit` means the modeled field is written to the target artifact; `drop` means the resource is suppressed when the field is present; `defer` means the field name is source-relative metadata but this IR layer has no bytes to materialize. Optional fields are emitted only when present, including explicit `false`, `0`, and empty lists where the target format can represent them. Canonical fields take precedence over same-named `Extra` fields only when emitted; conflicts produce one value-free `compile.canonical-field-overrides-extra` warning per field. Output and diagnostics are deterministic.

Every Devin hook/MCP case marked error above skips that aggregate entry and makes `sync` exit non-zero; warning cases emit their entry and only drop an inert sub-field or leave a plugin-root token unexpanded.

Windsurf workflow `auto_execution_mode` and Gemini subagent `mcpServers` are
reserved even when no typed value is present. Opaque extras cannot activate
these target-native controls; they are omitted with
`compile.canonical-field-overrides-extra`. Native Windsurf workflow modes are
loaded into the typed sidecar, preserving explicit empty strings; non-string
modes are rejected rather than coerced. Native Gemini inline servers continue
through typed token normalization and credential diagnostics.

## Model and reasoning policy

Subagent model selection uses the shipped `modelpolicy/catalogs/<harness>.yaml` files. It distinguishes native identifiers, exact provider models, floating family aliases, parent inheritance, and harness-default selection. Unresolved cross-harness models warn and omit the field, never the resource. No automatic cross-provider or nearest-effort substitution is performed. Model/effort/provenance extension keys are reserved even when the resolved field is absent, including case variants.

| Target | Subagent reasoning encoding | Inherited model |
|---|---|---|
| Claude | Cataloged separate `effort` | Omission or `inherit`; independently declared effort values may apply |
| Factory | Cataloged separate `reasoningEffort` | Omission or `inherit`; effort is omitted with a warning because native inheritance ignores it |
| Cursor | Cataloged parameters in the model string, such as `claude-opus-5[effort=high]` | Omission or `inherit`; no separate effort field |
| Gemini | Omit effort with a warning; native agent Markdown has no effort field | Omission or `inherit` |
| Devin | Cataloged reasoning levels encode into model-variant UIDs per `devin.yaml`; unsupported combinations warn and are omitted | Omission uses Devin's default; cross-harness parent inheritance warns, native default round trips do not |
| Codex | Cataloged separate `model_reasoning_effort` | Omit `model`; do not emit the literal `inherit` |

Native model strings and separate effort values retain `ModelSource` through ingestion and archives. Same-harness opaque selections round-trip without claiming current account availability. Exact versions never silently become floating aliases. A catalog's explicit family-to-version pin emits `model.selector-pinned`. Legacy model/effort sidecars remain readable; authoritative source-aware fields take precedence. Claude/Devin skill model fields share resolution, while other existing skill field policies remain unchanged and are not evidence of native model-override support.

The current model policy supersedes earlier alias-only and unconditional-effort descriptions. The [README maintenance recipe](README.md#update-a-shipped-model-catalog) identifies the data files and offline verification command.

## Codex target

The Codex cells were verified on 2026-08-19 against the official documentation
for [skills](https://developers.openai.com/codex/skills),
[subagents](https://developers.openai.com/codex/subagents),
[hooks](https://developers.openai.com/codex/hooks), and
[MCP](https://developers.openai.com/codex/mcp), with `oauth_resource` verified
in the [config reference](https://developers.openai.com/codex/config-file/config-reference).
Native fixture shapes are pinned
by `compile/codex/translator_test.go` and `ingest/codex/codex_test.go`; all five
target-materialized kinds also have Codex source/destination cells in
`testdata/matrix/*/matrix.yaml`, with `codex-to-*` golden trees for cross-target
output. The table states only mappings supported by those sources and fixtures.

| Resource field | Codex |
|---|---|
| Skill `name`, `description`, `body` | emit to `.agents/skills/<name>/SKILL.md`; canonical fields win over conflicting extras |
| Skill activation metadata (`argument-hint`, `model`, `triggers`, `subagent`, `agent`) | omit with warning `compile.codex.field-dropped`; the skill remains |
| Skill `allowed-tools` / `permissions` | any explicit value, including an explicit empty restriction, suppresses the artifact with error `skill.codex.security-restriction-unsupported`; Codex has no documented skill field that preserves these controls |

Loaders reject malformed or mixed typed security lists rather than silently filtering them. Explicit empty lists remain empty; permissions maps preserve unknown nested keys and reject non-object/null permission values. MCP and hook map-backed iteration is sorted by resource/event name. Secret values never occur in diagnostics or logs.

Constructors from earlier releases retain their fixed signatures. Rich typed fields use additive `*WithOptions` constructors and documented option functions. Support file bytes and D9 ownership/materialization remain outside this package.
