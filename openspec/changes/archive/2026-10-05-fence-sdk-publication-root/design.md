## Context

After SDK stage completion, root replacement bypasses the earlier metadata root snapshot and can rename independently authored foreign staged bytes. Replacing only the staging directory also supplies a new payload. Existing cleanup repeatedly reopens the staged public path.

## Decision

Capture output root and original staging directory after existing stage creation; match existing original root snapshot, and record the newly created real root when it was initially absent. Keep its native descriptor for publication/cleanup. Before each artifact publication revalidate named original root and original stage-directory object; create destination parents through EnsurePath and rename relative to the native root. Every cleanup uses original stage inode under the captured parent, treats prior successful removal as absence, preserves replacements and joins deferred error. Named report/error results retain primary policy/partial-result errors and close failures. Source comments stay intact. Stale actions get a root recheck but discovery/removal authority remains separate.
