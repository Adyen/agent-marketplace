## Context

Portable state is loaded for work discovery and per-target execution. Current metadata mutation reopens its lexical parent and uses path-based rename/remove, even after the selected native work has changed that namespace. The shared fsboundary primitives already provide strict captured destinations and descriptor-relative staging/publication/removal.

## Decisions

1. Extend the existing snapshot with admitted bytes and full file identity plus observed scope/parent directory identities; keep read admission, contained parent aliases, captured-size growth checks and absence/cleanup precedence intact.
2. Re-admit the scoped parent, require observed directory objects to match and capture a direct regular manifest destination. Check existence/full file state and bytes against the loaded snapshot before any metadata mutation, including no-op saves. Missing parents may be created through captured scope descriptors when publication requires them.
3. Stage under a captured parent and recheck the parent after staging. Shared destination publication/removal verifies leaf state and mutates descriptor-relatively; attempt cleanup unlinks only its staged name through that descriptor. These checks do not claim mutual exclusion against uncooperative namespace writers between validation and mutation.
4. Existing manifest permissions come from the loaded unchanged file generation. New manifests retain 0644. Identical desired bytes remain inode/mtime-neutral after admission; valid empty state removes only the loaded manifest.
5. Use the existing internal RunOption test-hook pattern for a deterministic after-staging witness, without an exported flag or production crash interface. No new size ceilings, supported-platform branches or global cache.
6. Scope is manifest authority only. A late metadata refusal does not roll back already-authorized native writes, and this slice does not fix portable output digests/tree/pruning or other ownership/backup consumers.

## Verification

Actual native mode-migration witnesses failed before removal and publication fixes: a replacement manifest was removed/overwritten, while the intended native migration completed. The review caught a loaded missing parent recreated by EnsureRoot before refusal: the real consumer witness failed before restricting creation to unobserved parents, then passed. Old-main native repeats fail inode/mode/mtime controls in both scopes; corrected writer preserves repeats and real update permissions/removal. Post-staging leaf/escaping-parent cases both scopes prove intended native updates, unchanged external/replacement bytes/identity/mode/mtime/aliases and cleanup in captured/replacement trees. Linux/macOS, scoped validate/lint/build, whole count-20 security-race script, v2/v4 CLI, strict specs and final combined E2E/configuration plus shellcheck pass. All 12 implementation entries including native/CLI/script/spec exclusions reviewed, none skipped. Existing fresh-install native portable disk/no-network lifecycle benchmark (2s ×5 macOS arm64) median 6.167ms → 15.211ms (+146.67%), 407438 → 416812 B/op (+2.30%), 4090 → 4216 allocs/op (+3.08%), p=0.008. This includes shared durable publication syncs and is not a speedup claim. Under concurrent gate load elapsed samples were more variable; five samples provide no 95% interval. Metadata no-op repeats avoid publication but no general lifecycle speedup is claimed.
