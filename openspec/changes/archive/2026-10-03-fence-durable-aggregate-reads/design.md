## Context

The ownership utility validates one opened final leaf but accepts independently resolved ancestors. Gemini's actual session can read a retargeted root and report an unchanged aggregate as healthy. Root-relative Store reads need the same authority across reconciliation, repair, mandatory safety backup, CAS and recovery live-payload checks.

## Decisions

Read only relative validated aggregate paths below the store's recorded canonical root. Capture strict ancestors from the Unix filesystem root, retain opened descriptors and use the shared destination snapshot's regular/single-link/nonblocking/size/read-state/named validation. Explicit target-root aliases already canonicalized by Store.Open remain supported; intermediate/final aliases and traversal cannot supply payloads. Preserve legacy os.IsNotExist for genuine absence before deferred cleanup so failed closes cannot become absence. Map shared unsafe/generation refusals to ownership sentinels without dropping causes or bytes. Absolute CAS/backup/recovery spellings first map under the recorded root; keep original AbsFile semantics rather than trusting a possibly mismatched Rel. No new arbitrary processing budget or exclusion of uncooperative writers. Store writes/staging/state/journal/archive consumers remain separate.
