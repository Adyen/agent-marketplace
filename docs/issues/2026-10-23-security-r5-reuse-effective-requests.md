# R5 Reuse Effective Requests During Runtime Adaptation

## Scope

This is independent, partial R53/F136 progress from main `4dfa9dae`, after
#943. R53, R5, #434, and performance track #765 remain partial. Neither the
frozen ledger nor its source index changes.

Git/directory runtime adaptation already interprets the group's requests
before adapting its exclusions. Pass that same effective request slice to
the exclusion helper instead of interpreting the group twice.

The private helper's nil argument retains its original lazy behavior;
Marketplace callers explicitly use that path. A non-nil argument is the
complete effective request slice for the same unchanged group, including
an empty-but-non-nil result. No persistent cache, cross-group sharing,
index, ceiling, deadline, or policy is introduced.

Final selections, required protection, first-exclusion order, repeated
re-inclusion, exact/wildcard/global rules, metadata, harnesses, provenance,
source/directory identity, diagnostic order, and publication behavior
remain unchanged. Inputs and acquisition locks are not mutated.

## Method

Raw evidence is in `security-r5-reuse-requests-2026-10-23/`:
`before.txt`, `after.txt`, `benchstat.txt`, and `manifest.json`.

- Go 1.27.3, darwin/arm64, Apple M4 Max; `GOMAXPROCS=16`,
  `GOGC=100`, `GOMEMLIMIT=off`, `CGO_ENABLED=0`, offline toolchain/modules.
- Six alternating before/after and after/before trials, one second per
  case: 25 identities, six samples per variant, 300 rows total.
- Original production blob: `2f57ba35ed90d93486abe7940ad6b5096b5e146b`.
- Delivered production blob: `25e41226c3fd3242ab8212b574cd38e0721a2bb2`.
- New benchmark blob: `c05624e292d762328e540ff2505f5c1edff33289`.
- Physical-path overlays compile the original production source and its
  original direct-helper tests together. Their private function arity
  differs; the delivered direct tests additionally exercise supplied
  requests. Both variants use identical benchmark and public Git/directory
  preservation definitions. Both source identities are recorded honestly.
- Source and binary fingerprints are checked during the run, all 300 rows
  are validated, and the retained table is regenerated byte-for-byte.
  Compiled code retains the request-interpretation call for nil arguments
  and branches around it for supplied requests.

The initial three-sample probes are separate and are not used for
significance claims. Some baseline cases have large timing outliers; they
are retained, not dropped. Directory timings therefore have wider
confidence intervals than the primary Git half-exclusion case.

All measurements are CPU-only, excluding parsing, directory setup,
include-tree disk reads, and network acquisition. The matrix includes
Git/directory sources at 1/256/1,024 skills with zero/half/all excluded and
an unrelated retained command; active selections with an unmatched exact
exclusion; wildcard controls; Marketplace lock hydration; and public
adaptation of 64/1,024 repeated exclusion/re-inclusion rounds.
The reused older active/Marketplace benchmarks retain their existing
in-loop assertions in both variants. The Git/directory and new public
churn checks run after `b.Loop`.

The half-excluded Git case saves 501,040.5 B/op and 1,062 allocations;
the directory counterpart saves 501,041 B/op and 1,062 allocations.
The full-exclusion cases save 449,360 B/op and 1,067 allocations.
The active-selection case saves 544,987 B/op and 1,046 allocations.
Repeated decisions save 832 B/op and three allocations.

Healthy Git and large wildcard timing controls show no significant
difference; their allocation counts and bytes are unchanged. The healthy
directory case and 256-request wildcard control have small nominal timing
deltas amid the full set of comparisons; no material speed-up claim rests
on them. Marketplace allocation counts/bytes are unchanged. No parsing,
end-to-end I/O, universal latency, or processing-budget claim is made.

Allocation profiles locate the repeated interpreter under exclusion
adaptation before reuse; the delivered supplied-request path no longer
needs that call. Profile totals are not compared because the faster variant
executes more operations; paired B/op is the per-operation evidence.

## Preservation And Negative Controls

Both variants pass the same public Git/directory decision fixtures,
include-tree consumer checks, and 1,000 generated replay-oracle cases.
The delivered direct-helper tests check both nil and supplied requests.
The public fixtures retain an unrelated command and assert include/exclude
order, required/replacement/re-inclusion behavior, wildcard flags, complete
authored decisions, and unchanged configuration bytes.

After timing, an additional public Marketplace witness is added and run
against both variants. It proves that lazy nil fallback suppresses an
exclusion of a protected selected resource while retaining a genuinely
unselected exclusion, with unchanged configuration/lock bytes.
It does not change the measured production or benchmark definitions.

Three private-overlay mutations fail their public consumers: passing
authored includes instead of effective requests, passing an empty snapshot
for every group, and removing the lazy Marketplace fallback. Focused
request/exclusion/public-adapter races pass in 2.328 seconds.
On the measured base, all remaining local gates pass:

- Explicit offline `GOWORK=off go mod tidy -diff` has no output and makes no
  dependency-file changes.
- Selected config/pipeline/resolver/TUI validation, vet, zero-issue lint,
  and build pass. This is not a local full-root-suite claim.
- Strict specs pass 66 items, 1,199 scenarios, 1,962 annotations, and two
  active changes.
- All 59 terminal journeys plus four utilities pass, zero skips, after
  frozen offline dependency installation without downloads/lock changes.
- Fresh combined E2E/configuration validation passes in 740.006 seconds:
  3,427 invocations, all 113 requirements, no gaps, all three required
  refusal witnesses executed/passed, and included shellcheck.

Host adversarial `open-code-review-delegate` accounts for all eleven own
files, including excluded tests/docs/raw evidence and the manifest.
Caller freshness, nil/empty handling, Marketplace lazy fallback, required
protection, diagnostics, mutation witnesses, all 300 rows, source/binary
identities, and timing qualifications are checked. Zero files are skipped;
no actionable finding remains. Private measurement/control harnesses are
also inspected; neither passing tests nor this review proves absence of
all defects.

## Reproduce

Build the original and delivered test binaries with identical benchmark
definitions. For the original private helper arity, overlay the original
`internal/config/v4_exclusion_processing_test.go` with the original
production source from `4dfa9dae`. Keep outputs separate:

```sh
go test ./internal/config -run '^$' \
  -bench '^(BenchmarkV4SparseExclusionAdapterCPU|BenchmarkV4DirectoryRequestReuseCPU|BenchmarkV4ActiveExclusionAdaptation|BenchmarkV4WildcardAdapterCPU|BenchmarkV4MarketplaceLockHydration|BenchmarkV4RequestReuseChurnCPU)$' \
  -benchtime=1s -count=6 -benchmem
benchstat before.txt after.txt
```

For the recorded interleaving, compile each binary once with `go test -c`,
alternate them for six trials with `-test.count=1`, and verify the 25
identities and six samples per variant. Match the manifest settings.
